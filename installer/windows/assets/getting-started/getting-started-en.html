Start with the component you installed

PLwC Gateway is the shared local core. Claude Desktop, Codex, Odysseus, and Chat Bridge are separate optional client paths. Complete only the cards for the components you selected in Setup.

Check your selection: open %APPDATA%\PLwC\config\installer\installation-summary.txt from the Start menu entry PLwC installation summary. It records the selected components and the exact prepared paths.
Always installed

PLwC Gateway only

The Gateway contains the governed workspace, profiles, and eight public tools. It does not provide a chat window by itself.

  1. Keep the installation summary for the runtime and data paths.
  2. To use PLwC interactively, add one of the client integrations below through Setup Repair.
  3. Docker may remain unavailable in Safe Mode; onboarding, profile compile, Reflection, Governor, diary, and Trashcan workflows remain available.
Claude Desktop MCPB

Finish Claude Desktop setup

Setup verifies and copies the unsigned MCPB package, but Claude Desktop owns the final import.

  1. Open Claude Desktop, then Settings > Extensions > Advanced settings, and enable Developer Mode.
  2. Select Install Extension and choose %APPDATA%\PLwC\app\packages\plwc-gateway-1.0.0.mcpb.
  3. Restart Claude Desktop if requested. Confirm that plwc-gateway exposes exactly 8 tools.
  4. Describe PLwC tasks normally. Claude receives the schemas through MCP; the Bridge Primer is not used.
Codex STDIO

Activate the generated Codex snippet

Setup creates a reviewed TOML definition and deliberately leaves the existing Codex configuration unchanged.

  1. Open %APPDATA%\PLwC\config\clients\codex\plwc-gateway.generated.toml.
  2. Merge its single [mcp_servers.plwc-gateway] table into %USERPROFILE%\.codex\config.toml. Do not create a duplicate table.
  3. Restart the Codex app, CLI, or IDE extension. Use /mcp to verify that plwc-gateway is enabled with 8 tools.
  4. Describe the result you want. Codex reads the MCP schemas directly; no Bridge Primer is required.
Odysseus STDIO

Import the portable Odysseus descriptor

The active Odysseus configuration location depends on that installation, so Setup prepares a portable JSON descriptor without changing the host.

  1. Open %APPDATA%\PLwC\config\clients\odysseus\plwc-gateway.generated.json.
  2. Import or merge its single plwc-gateway entry into the active Odysseus MCP server configuration.
  3. Restart Odysseus and confirm one PLwC server with exactly 8 tools.
  4. Use normal requests. Odysseus receives tool schemas over STDIO MCP and does not use the Bridge Primer.
ChatGPT browser

Finish Chat Bridge setup

Setup installs the local Bridge, registers Native Messaging, and enables per-user automatic startup. The unpacked browser extension still has to be loaded.

  1. Open the extension folder offered on Setup's Finish page, or use <selected Chat Bridge directory>\extension.
  2. On the Chrome, Edge, or Brave extensions page, enable Developer Mode and choose Load unpacked. Select that extension folder.
  3. Reload ChatGPT, open the PLwC panel, and confirm matching builds and Tools 8 / 8.
  4. Follow the Bridge-only Primer steps in the next section.
Every configured client uses the same PLwC workspace and active profile. Only Chat Bridge needs a Primer in each new conversation; native MCP clients receive the tool schemas directly.

Configure PLwC independently of the chat client

Open PLwC configuration from the Windows Start menu. The local page works with Gateway-only, Claude Desktop, Codex, Odysseus, and Chat Bridge installations and writes the shared Gateway settings used by all of them.

Governed state

Active profile

Choose which profile future PLwC calls load. Select Review activation, inspect the Governor plan, and explicitly confirm it. The page never edits the protected active-profile state directly.

Guided onboarding

Create a new profile

Select New profile, describe identity, collaboration, memory, and confirmation boundaries, then review the Governor plan. No protected file is created until you explicitly confirm the plan; the completed profile becomes active.

Shared thresholds

Memory, Persona, and Temperament

Set how many independent evidence points are required before confirmed Reflection candidates may be promoted into durable profile knowledge. Higher values are more conservative.

Compile context

Persona Layer

Switch whether future Compiles include the Persona Layer. Turning it off does not remove or rewrite PERSONA.md; it changes only the context PLwC compiles for later calls.

Optional search

Qdrant

Allow or disable use of the configured Qdrant vector index. Enabling it does not create or rebuild an index; reindexing remains a separate governed operation.

Saved values apply to the next PLwC call. Restart only a client that still displays cached values. The page runs locally on 127.0.0.1, uses no remote assets, and closes after inactivity.

Chat Bridge only: your first browser conversation

Skip this section for Claude Desktop, Codex, or Odysseus. In ChatGPT, the Bridge Primer is the operating contract and must be inserted once at the beginning of every new conversation.

1

Open a fresh chat

Open ChatGPT and select the PLwC icon beside the composer to open the Chat Bridge panel.

2

Verify the connection

In Status, confirm Bridge connected, matching build identity, and Tools 8 / 8. Use Reconnect if needed.

3

Insert the Primer

Open Primer, select Generate, then Insert Bridge Primer. The Primer is generated from the eight live tool schemas.

4

The Primer is inserted into the ChatGPT composer but is not sent for you. Send it manually, wait for the reply, and then describe the PLwC task in your own words.

Use natural language, not JSON

You do not need to memorize tool names or write a plwc_tool_call wrapper. Once your selected client reports one plwc-gateway server with exactly 8 tools, describe the result you want. Claude Desktop, Codex, and Odysseus receive the tool schemas directly through MCP. Chat Bridge receives the same contract through its Primer.

If an operation or argument is uncertain, ask the AI to inspect plwc_describe with a precise scope or operation filter before acting. It must not guess a tool operation. Read-only calls may run automatically. Writes, moves, Governor apply, and other mutating calls remain confirmation-bound in every client.

Core workflows

These workflows are the same in Claude Desktop, Codex, Odysseus, and Chat Bridge. The client transports the request; PLwC applies the same profile, confirmation, and governance rules.

Status and Describe

In plain language: Status tells you what is active and healthy. Describe explains which operations and arguments a PLwC tool accepts.

  • Use Status at first start, after configuration changes, or when a workflow behaves unexpectedly.
  • Use Describe when the AI is unsure about an operation. It should inspect the schema instead of guessing.
  • What changes? Nothing. Both are read-only checks.

Onboarding

In plain language: Onboarding creates the first usable PLwC profile from your answers. It establishes how the assistant should address you, work with you, remember information, and ask for confirmation.

  • Use it when first-run status reports that no valid active profile exists, or when deliberately creating a new profile.
  • What changes? The plan changes nothing. Only the confirmed Governor apply creates the protected profile files and activates the profile.
  • Expected result: runtime status reports a valid active profile with no missing required files.
Natural-language request Check my first-run state. If a profile is missing, ask the onboarding questions, prepare a profile-creation plan, show it to me, wait for explicit confirmation, apply it through the Governor, and verify runtime status afterward.

The correct sequence is status, Governor plan, explicit user confirmation, Governor apply with confirmed=true, and a read-only runtime check. Protected profile files must never be created manually.

Compile

In plain language: Compile does not compile program code. It reads the active profile and assembles the relevant parts into one controlled context layer that the AI can use in the current session.

  • What is loaded? The stable core rules plus the applicable temperament, Persona, Memory, and optional task context. Governance and hard safety gates remain attached.
  • When to use it: use boot at the start of normal work, working when the current task needs precise extra context, and full for a complete audit or transport diagnosis.
  • What changes? Nothing in the profile. Compile is read-only and returns a context layer. Including or excluding the Persona Layer changes this returned layer, not PERSONA.md.
  • boot: compact everyday profile load for a new session.
  • working: profile load plus a precise description of the current job.
  • full: complete profile layer for audit and diagnosis; larger than normal working context.
  • persona_layer=true: includes the Persona Layer in this returned context. Chat Bridge Settings can control its default there.
Natural-language request Load my active profile in boot mode for this session, include the Persona Layer, and summarize which profile and context sections were loaded. Do not modify any profile file.

Reflection

In plain language: Reflection is a review notebook for observations that may be useful later. It records a candidate with evidence and confidence, but does not immediately turn that observation into permanent Memory or personality.

  • Use it when a session produced a reusable lesson, preference, correction, or successful working pattern that deserves later review.
  • What changes? After confirmation, only reflection.md receives the candidate.
  • What happens later? The Governor can promote sufficiently supported candidates to Memory or Persona in a separate plan and apply workflow.
Natural-language request Draft a Reflection about the reusable insight from this session. Include a real evidence date and trust level, show the proposed entry, and ask before writing it. Do not promote it directly to Memory.

A Reflection write records a candidate in reflection.md. It does not directly change memory.md or PERSONA.md. Promotion is a separate Governor plan and apply.

Governor

In plain language: The Governor is PLwC's approval and safety layer for durable profile changes. It checks whether a proposed change has enough evidence, belongs in the target file, conflicts with existing content, or duplicates something already known.

  • Plan is a preview and decision report. It shows the exact target, content, evidence, thresholds, conflicts, and provenance without writing.
  • Apply performs only the reviewed plan and still requires explicit confirmation.
  • Use it for onboarding and permanent promotion into Memory, Persona, or Temperament. Do not use it for ordinary temporary task context.
Natural-language request Prepare a Governor plan for this candidate. Explain the target, evidence, threshold decision, duplicates, conflicts, and provenance in normal language. Do not apply it until I confirm the exact plan.

Diary

In plain language: The diary is a human-readable chronological record of a day or session. It preserves decisions, outcomes, and context so you can inspect the history yourself.

  • Use it when you want a readable account of what happened, what was decided, and what should be continued later.
  • What changes? Only the confirmed file under Tagebuch/. A diary entry is not automatically Memory or Persona.
  • What happens later? A read-only diary scan can propose stable candidates, which still require Governor review before entering the profile.
Natural-language request Draft a compact entry for Tagebuch/YYYY-MM-DD.md that records today's decisions and verified results. Show me the exact text and ask for confirmation before writing.

The diary is a governed workspace record, not automatic Memory. PLwC never writes it in the background and never treats it as truth without later review.

Trashcan instead of deletion

In plain language: PLwC removes a file from its working location by moving it to Trashcan/. It does not permanently delete files.

  • Use it when a workspace file should no longer remain in its current folder but may need to be inspected or restored later.
  • What changes? The confirmed file path changes from the exact source to the exact Trashcan target.
  • Safety behavior: PLwC asks for confirmation, never empties Trashcan automatically, and stops on a target-name conflict.
Natural-language request Move Temp/example.txt to Trashcan/example.txt. Show the exact source and target and wait for my confirmation.

PLwC has no public delete operation. Trashcan/ is a normal move destination, is never emptied automatically, and does not invent a replacement name when the destination already exists.

Grow the personality from the diary

In plain language: Persona promotion turns a repeatedly supported preference or collaboration pattern into part of how the assistant works with you. It is for durable behavior, not a one-day mood or isolated event.

  • Use it when diary evidence shows a stable way you want to be addressed, supported, challenged, or accompanied across sessions.
  • What changes? The diary scan changes nothing. Only a confirmed Governor apply can update PERSONA.md.
  • Why provenance matters: the source file, heading, and hash prove exactly which diary evidence was reviewed.

Diary content is never copied automatically into the profile. Use a read-only scan first, then a governed Persona promotion with source provenance.

  1. Ask the AI in your selected client to scan the active profile's diary with plwc_profile(operation="scan_tagebuch").
  2. Review the proposed stable preference, interaction style, working pattern, or inner-perspective candidate.
  3. Ask for a plwc_governor plan with plan_type="persona_promotion". When a diary section is the source, the plan should include source_file and source_heading.
  4. Review the canonical source SHA-256 returned by the plan. Confirm only the exact plan you intend to keep.
  5. Apply with confirmed=true and the exact returned source provenance, then compile the profile again.
Natural-language request Scan my diary read-only for a stable preference or collaboration pattern that could improve the Persona Layer. Show the evidence and source section, prepare a Persona-promotion plan, and do not apply anything until I explicitly confirm.
A diary story, one successful test, or a temporary mood is not automatically a durable personality trait. Let the Governor enforce evidence, trust, semantic, duplicate, and conflict checks.

What force means

In plain language: Force is a tightly limited exception for a user who deliberately accepts that a promotion has not yet reached a normal evidence or marker threshold. It is not a faster mode, an administrator master key, or a way to ignore safety rules.

  • Use it when a normal Governor plan has rejected an otherwise supported promotion only with insufficient_marker or insufficient_evidence, and you have reviewed that reason.
  • What changes? force=true alone changes nothing. A separately confirmed Apply performs the exact reviewed promotion and records the override in the profile journal.
  • What remains protected? Semantic quality, trust, duplicate and conflict checks, source integrity, cross-profile boundaries, protected paths, and the absence of permanent deletion cannot be bypassed.
Safe request before considering force Explain the Governor denial and tell me whether it is only a threshold-style denial that supports force. Do not rerun with force and do not apply anything yet.

Restart and reload guidance

  • If Setup reports that Windows must restart, close Setup and restart before trying the installation again.
  • After installing or updating Docker Desktop or WSL, restart Windows before the first Docker-backed sandbox or document acceptance test.
  • After importing the MCPB, restart Claude Desktop if the PLwC extension or its eight tools do not appear.
  • After changing the generated Codex or Odysseus configuration, restart that client and recheck its MCP server list.
  • After updating the unpacked Chat Bridge extension, select Reload on the browser extension page and reload the ChatGPT tab.
  • Save & Restart in Bridge Settings restarts the managed Gateway child. Wait for Status to return to connected and 8 / 8; use Reconnect if needed.
  • A Gateway-only install with no prerequisite restart request normally does not require a Windows restart.
